# 声骸联合优化与动态强化

Agent 执行流程、异常恢复和交付要求见 [声骸强化 Agent 操作手册](echo-enhancement-agent-guide.md)。本文说明模型和日志口径。

第二步任务 `ModelEnhanceEchoTask` 使用 `AdaptiveEnhancementSession`。默认仍是离线模拟；关闭 `Simulation Only` 后才进入游戏。原来不使用数学模型的批量强化规则，以及供历史记录重放使用的 `EchoEnhancementSession` 保持兼容。

## 默认规则

| 配置 | 默认值 | 含义 |
|---|---:|---|
| Candidate Switch Ratio | 1.25 | 另一有库存目标效率达到当前目标的 1.25 倍时切换 |
| Missing Candidate Stop Ratio | 0.50 | 最佳可用胚子效率不足最佳缺货目标的一半时停止开启新胚子 |
| Fresh Candidate Samples | 20,000 | 新胚子比较使用的共同随机样本数 |
| Maximum Decision Samples | 80,000 | 接近切换/停手边界时的加密采样上限 |
| Max Candidates Per Run | 0 | 新配置默认连续处理，直到策略停手、缺货或材料不足 |
| Pause after Success | false | 新配置默认在保留后继续重新评估 |
| Max Candidate Search Pages | 30 | 每个排序方向最多搜索的页数，达到上限不等于确认缺货 |
| Decision Log Directory | artifacts/echo_inventory/enhancement_runs | 每轮独立的决策证据目录 |

已有用户保存的单轮上限和成功暂停设置仍然生效。要让动态切换连续执行，可设置 `Max Candidates Per Run=0`、`Pause after Success=false`。两个比例是根据本次评估选取的起点，可在任务配置中调整；不是保证收益最优的常数。

## 何时联合优化

任务加载第一步结果中的**全部满级库存**，包括当时不构成单件提升的版本。每个新声骸达到 +25 后都重新计算完整组合，遵守 COST、主词条、同名唯一和共鸣效率约束。主词条不同的库存不能混入候选。

例如，带充能的新 1C 可以让库存中攻击词条更好的无充能 3C 上场。这种提升不会被限制为“当前这一件只能换一个槽”。评分相同时优先保留当前逻辑槽位，减少无意义的交换。

联合优化刷新的是**逻辑配装**和后续比较基准。强化任务会锁定要保留的声骸，**不会自动执行游戏内换装**；日志中的 `equipment_applied_in_game=false` 明确标记这一点。

不在当前最优组合中、但在同名声骸中没有被另一件同时以非充能评分和充能值压过的版本，可以锁定为将来的联合配装备选。完全重复或被压过的版本可标记弃置。候选的必需词条规则仍然生效。

## 如何选择下一件

1. 对每个“名字 + COST + 主词条”候选补全五条副词条，计算放入完整库存后的联合正提升。
2. 用平均正提升除以预期净材料占当前瓶颈资源的比例，得到效率；分开记录提升概率、成功时收益、预计保留概率和成本。
3. 同时维护最佳合法目标和最佳可用目标。缺货目标仍参与机会成本比较，避免把弱库存重新定义成“最优”。
4. 当前目标还有库存时，只有其他目标达到切换倍率才切换；但当前目标不得借此绕过缺货停手线。
5. 如果最佳目标缺货而另一个目标效率接近，继续后者。例如 3C 缺货、4C 仍在 50% 线以上时，并不会仅因 COST 不同而停止。
6. 接近边界时增加共同样本。加密后仍跨越缺货停手线的置信区间，则以 `stop_uncertain` 停下，供用户或 agent 判断。

概率是“补全到 +25 后能提高当前联合最优”的采样估计，不是逐级策略的保证成功率。均值置信区间按样本标准误估算；零成功样本只表示此次采样没有观察到提升。半成品每次开孔后重新评估，并继续使用原有 0.9 机会成本阈值。

极品同名声骸会自然降低该名字的边际收益，无须再人为乘一个降权系数。`3C > 1C > 4C` 的获取难度以定性信息记录，未编造获取时间或把稀有度乘到强化收益上。

## 库存确认

实机不会直接相信旧检查文件中的胚子数量。先按排名搜索目标：读取 +0 详情，两次确认名字、COST 和主词条，数量也需两次读数一致。卡片上的无符号数字是堆叠数量，不是等级。

- `unknown`：尚未确认，或知道有胚子但数量无法可靠读取。
- `present`：已确认有可用胚子；数量可以仍然未知。
- `missing`：完整搜索未发现，或经确认的堆叠数量已被消耗完。

首次成功读回开孔结果时才扣减一个胚子；后续孔位不重复扣数量。搜索中发现同套装、兼容主词条的新名字，会加入候选池并在花材料前重新排名。

搜索会检查等级排序的两个方向，使用滚动前后库存区域是否变化作为到末尾的证据。若达到翻页上限，或存在无法读取的详情，则停止并记录 `search_incomplete`，不将目标标成缺货。搜索截图保存在同一日志目录中。

## 材料的两本账

**可花余额**只记录现实中可用的调谐器和经验。标记弃置不会增加余额。首次开孔前和每次继续开孔前都必须有足够材料。

**经济成本**扣除预计返还，用于选择目标和半成品停手：

`后续投入 + 当前声骸立即回收的价值 − 最终可弃置概率 × 满级返还`

预计要锁定为备选的声骸不会被计算成可回收，因此“保留概率”可能高于“立即提升概率”。这会让成本比仅按成功概率计算的早期评估更保守。机会成本和净耗都不影响可花余额。

当前沿用 `ResourceCostModel` 的调谐器 30%、经验 66% 有效返还假设。它们是模型参数，尤其 66% 不是本次实测固定返还率。阶段投入的多余经验、实际经验管消耗与回收取整仍需通过实际读数校准。

有 OK-WW 资源 provider 时，每件结束后重新读取可用余额。读取失败会保留当前账本，并记入 `resource_read_unavailable`，不会用最初的手工预算覆盖已消耗余额。模型毛投入与权威余额修正分开保存，以免把背包变化擅自解释成回收或消耗。

任务不会自动回收声骸。

## 用户与 agent 如何查阅日志

任务信息中的“强化决策日志”指向本轮 `summary.md`。默认目录为：

`artifacts/echo_inventory/enhancement_runs/<时间戳>/`

| 文件 | 用途 |
|---|---|
| summary.md | 停止原因、最新候选排名、概率、效率、剩余数量和材料口径 |
| latest.json | 当前逻辑配装、活动候选、最新排名、阈值、采样量、成本参数和库存证据 |
| events.jsonl | 带序号和 UTC 时间的追加事件，每条都含当时状态；便于逐步复盘 |
| candidate_*_*.png | 强化点击前与成功读回后的截图 |
| search_*.png | 判断库存、搜索未完成或缺货的页面证据 |

主要事件：

| kind | 含义 |
|---|---|
| session_start | 来源检查文件、原装备、全部已知完成品、模型假设 |
| stock_observation / search_incomplete | 数量与身份的读取证据，或为什么不能确认缺货 |
| candidate_ranking | 全体目标的效率排名、置信区间、相对最佳效率、调度结论 |
| candidate_started | 已选择的胚子；此时尚未扣减数量或材料 |
| enhancement_decision | 当前已揭晓词条、继续/弃置/保留原因、成本与阈值 |
| upgrade_click_intent / upgrade_clicked | 即将点击和已发出点击的边界，便于区分 OCR 中断时的材料状态 |
| reveal / reveal_recorded | 新词条、毛成本扣账和读回截图；首次揭晓才扣一件胚子 |
| joint_optimization | +25 后的联合配装前后对照、变化槽位和总分差 |
| kept / discarded | 保留用途，或待回收数量；不会凭空增加可花余额 |
| resource_observation | 可用余额的权威重读；保留原模型账本便于对账 |
| stopped | 完成、策略停手、材料不足或异常原因 |

`unreconciled_upgrade=true` 表示有一次强化点击尚未成功读回并完成记账。此时可能已经花费材料，必须先核对截图、实际等级和余额，不能按日志旧余额盲目重试。日志用于审计和恢复依据，当前没有自动从 JSONL 接续执行游戏的入口。

建议复盘时先看停止原因和库存证据，再比较 1.25/0.50 阈值与置信区间，最后检查全套配装与毛/净材料成本。不要只凭成功概率或单个槽位原始分数调参。

## 离线模拟和验证

模拟与实机使用同一个 `AdaptiveEnhancementSession`。检查文件可提供：

```json
"inspection": {
  "fresh_stock": [
    {"identity": {"name": "封庭械囿", "cost": 3, "compatibility": "cost_3:havoc_damage"}, "count": 0}
  ]
}
```

未提供数量的候选在模拟中视为可持续获取，日志会注明这个假设；实机则先搜索确认。要模拟真实缺货，应为全部候选、当前装备和兼容满级库存中的名字提供数量，包括零库存。

本次开发用第 90 件及之前的观测构建检查点，验证了新策略会在仅剩低收益 1C 时给出 `stop_missing_stock`。未使用第 90 件之后的词条参与该决策，也未把缺失的未来词条伪装为完整反事实回测。

另外两个检查点：开局允许选择有库存的封庭；原记录第 54 件时，加密到 80,000 个样本后仍在 50% 停手线附近，返回 `stop_uncertain`。因此新规则可能比原流程更早暂停，需要根据日志决定是否继续，不能承诺一定复现原记录第 90 件的极品结果。

可使用 `scripts/replay_echo_adaptive_checkpoint.py` 复现单个状态判断，传入原 campaign 目录、`--check` 检查文件、`--stock` 开局已核验数量文件和 `--through` 已完成件数。工具仅使用该序号及之前的词条与投入，生成与正式任务相同格式的日志。

核心代码：`src/echo/joint.py`、`src/echo/adaptive.py`、`src/echo/decision_log.py`；任务入口：`src/task/ModelEnhanceEchoTask.py`；回归测试：`tests/test_echo_adaptive.py`、`tests/test_echo_adaptive_task.py`。
